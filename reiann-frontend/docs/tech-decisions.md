# Reiann Tech Decisions

อัปเดต: 7 พ.ย. 2569 · ใช้คู่กับ `product-spec.md` และไฟล์ Figma `StudentHub — Strawberry Matcha Demo`

## ตัดสินใจแล้ว

| เรื่อง | ทางเลือก | หมายเหตุ |
|---|---|---|
| Frontend | Next.js + Tailwind | กราฟวิชาใช้ React Flow ร่วมกับ ELK หรือ Dagre ตาม spec |
| Backend และฐานข้อมูล | Supabase (Postgres) | ใช้ระบบเข้าสู่ระบบ ที่เก็บไฟล์ และ pgvector สำหรับ RAG ได้ในที่เดียว |
| วิชาที่เรียนและเกรด | อัปโหลด transcript แล้วแก้เองได้ | อ่านเฉพาะรหัสวิชา ภาค และเกรด ไม่เก็บชื่อ รหัสนิสิต หรือเลขบัตรประชาชน |
| เส้นทางอาชีพ | พักไว้ | ซ่อนจากเมนูและหน้าวิชา จะกลับมาทำด้วย RAG + LLM |
| หนังสือมือสอง | เป็นพื้นที่ลงประกาศ ไม่มีระบบส่งคำขอ | ช่องทางติดต่ออยู่ในหน้ารายละเอียด เห็นเฉพาะนิสิต KU ที่เข้าสู่ระบบ |
| ภาษาในข้อมูล | ชื่อคณะ สาขา และวิชาใช้อังกฤษนำ ไทยรอง | เมนูและข้อความในหน้ายังเป็นภาษาไทย |
| ขอบเขตหลักสูตร | รองรับทุกคณะทุกสาขา | เริ่มจากข้อมูลจริงของ Computer Science หลักสูตร พ.ศ. 2565 |
| ลงวิชาซ้ำ | ใช้เกรดครั้งล่าสุด | ครั้งก่อนแสดงเป็นประวัติ ไม่นับซ้ำ |
| GPAX | ทศนิยม 2 ตำแหน่ง | คำนวณค่าเต็มแล้วตัดเศษตอนแสดง ดู `frontend-flows.md` หัวข้อ 5 |
| เงื่อนไขวิชา | ต้นไม้ `all` / `any` เก็บเป็น jsonb | รองรับ "หรือ", "เรียนพร้อมกัน" และ "เคยเรียนแล้ว ไม่ผ่านก็ลงได้" ดู `frontend-flows.md` หัวข้อ 5.1 |
| เปลี่ยนบัญชีขณะมีข้อมูลค้าง | ใช้ข้อมูลของบัญชีที่เพิ่งเข้าสู่ระบบ | ลบข้อมูลที่ค้างบนเครื่องของบัญชีเดิม |
| มือถือ | ไม่ทำใน MVP | ยกเว้นหน้าเปิดลิงก์แชร์ตาราง และรูป wallpaper |
| ขนาดรูป wallpaper | มือถือ 1170×2532, แท็บเล็ต 2048×2732, คอมพิวเตอร์ 2560×1440 | ค่าเริ่มต้นคือมือถือ ดู `frontend-flows.md` หัวข้อ 5.2 (ตัดสินใจ 7 พ.ย. 2569) |
| LINE | ไม่ทำแจ้งเตือนผ่าน LINE | การแจ้งเตือนใช้อีเมล ยังเก็บช่อง LINE ID ไว้เป็นช่องทางติดต่อซื้อชีทและหนังสือ (ตัดสินใจ 7 พ.ย. 2569) |

## ขอบเขต MVP แรก

ตัดสินใจเมื่อ 7 พ.ย. 2569

| เรื่อง | ขอบเขต |
|---|---|
| Feature | ตัวคำนวณเกรด และตารางเรียน (แชร์ลิงก์ + บันทึกเป็นรูป wallpaper) |
| ผู้ใช้กลุ่มแรก | เพื่อนและรุ่นใน Computer Science |
| การเข้าสู่ระบบ | บัญชี Google ทั่วไปชั่วคราว จนกว่าจะได้ข้อสรุปเรื่อง @ku.th |
| ส่วนที่นิสิตช่วยกันเขียน | ยังไม่ใส่ใน MVP แนะนำให้รอจนยืนยันตัวตนนิสิต KU ได้ เพราะ spec กำหนดว่ารีวิว ถาม-ตอบ และประกาศต้องยืนยันว่าเป็นนิสิต KU |

สิ่งที่ MVP ต้องมีเพื่อให้ 2 feature นี้ใช้ได้:

- **รายวิชา CS หลักสูตร พ.ศ. 2565:** รหัส ชื่อไทยและอังกฤษ และหน่วยกิต ใช้เลือกวิชาในตัวคำนวณและตารางเรียน
- **อัปโหลด transcript:** ใช้คำนวณผลต่อ GPAX และดึงรายชื่อวิชาที่ลงในภาคปัจจุบัน
- **กรอกวันเวลาเรียนเอง:** ยังไม่มีข้อมูลหมู่เรียนจากแหล่งทางการ
- **ลิงก์แชร์ตาราง:** สร้างได้หลังเข้าสู่ระบบ ตั้งวันหมดอายุได้ และยกเลิกได้ทุกเมื่อ
- **สร้างรูป wallpaper บนเครื่องผู้ใช้:** ไม่ต้องส่งข้อมูลขึ้น server

ยังไม่อยู่ใน MVP: กราฟวิชา ค้นหาและหน้าวิชา รีวิว ชีทสรุป ถาม-ตอบ วันสอบและงาน หนังสือมือสอง และเส้นทางอาชีพ

## รอคุยก่อนตัดสินใจ

| เรื่อง | ทางเลือก | ผลต่อการเขียนโค้ด |
|---|---|---|
| การยืนยันว่าเป็นนิสิต KU | Google เฉพาะ @ku.th · ส่งรหัสทางอีเมล @ku.th · KU SSO | ทำ auth เป็นชั้นแยกไว้ก่อน แล้วค่อยเลือกวิธี |
| ดึงเกรดผ่านบัญชี KU | ขึ้นกับว่ามหาวิทยาลัยอนุญาตหรือไม่ | ระหว่างนี้ใช้การอัปโหลด transcript |

## ยังต้องตัดสินใจ

1. **เกณฑ์ปิดบัญชี Google ทั่วไป:** เมื่อได้วิธียืนยัน KU แล้ว จะย้ายบัญชีเดิมอย่างไร
2. **Hosting:** เช่น Vercel คู่กับ Supabase และงบรายเดือน
3. **การตรวจเนื้อหา:** ใครดูรายงานรีวิว ชีท และประกาศ จะซ่อนอัตโนมัติเมื่อถูกรายงานกี่ครั้ง
4. **รูปในประกาศหนังสือ:** อัปโหลดรูปได้ไหม ถ้าได้ ต้องใช้ที่เก็บไฟล์และกติกาเรื่องเนื้อหา
5. **รีวิวหนังสือ:** ใน Figma เป็นรีวิวผู้ลงประกาศ หรือควรเป็นรีวิวตัวหนังสือ
6. **ข้อมูลหลักสูตร:** ใช้สคริปต์ดึงจากเว็บคณะหรือกรอกเอง และใครตรวจความถูกต้อง
7. **การเก็บ transcript:** อ่านไฟล์บนเครื่องผู้ใช้ทั้งหมด หรือส่งขึ้น server แล้วลบทันที
8. **Analytics และ log:** เก็บอะไรได้บ้างโดยไม่ระบุตัวตน
