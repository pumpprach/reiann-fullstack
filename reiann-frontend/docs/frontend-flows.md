## 2. Guard ก่อนเข้าแต่ละหน้า

ตรวจตามลำดับนี้ใน middleware หรือ layout

1. **ยังไม่เข้าสู่ระบบ** และ route ต้องเข้าสู่ระบบ → ไป `/sign-in?next=<path เดิม>` หลังเข้าสู่ระบบแล้วกลับไปที่ `next` (ยอมรับเฉพาะ path ภายในเว็บ ห้าม redirect ไปโดเมนอื่น)
2. **ยังไม่เลือกหลักสูตร** → ไป `/onboarding/program`
3. **ยังไม่ผ่านขั้น transcript** (ไม่อัปโหลดและไม่กดข้าม) → ไป `/onboarding/transcript`
4. **เข้าหน้า onboarding ทั้งที่ทำครบแล้ว** → ไป `/` ยกเว้นมาจาก Settings เพื่อเปลี่ยนหลักสูตรหรืออัปโหลดใหม่
5. **หน้าที่ต้องยืนยันนิสิต KU** (ส่วนที่นิสิตช่วยกันเขียน) แต่บัญชียังเป็น Google ทั่วไป → อ่านได้ แต่ปุ่มเขียนแสดงเหตุผลว่าต้องยืนยันก่อน ไม่ซ่อนปุ่ม
6. **หลักสูตรที่เลือกยังไม่มีข้อมูลแผนการเรียน** → หน้าที่ใช้แผน (`/courses/graph`, `/courses/plan`, `/courses/what-if`) แสดง No Plan Yet ส่วนตัวคำนวณเกรดและตารางเรียนยังใช้ได้

`/s/[token]` ไม่ผ่าน guard ข้อ 1–6 เพื่อให้เพื่อนที่ไม่มีบัญชีเปิดดูได้

## 3. สถานะที่ทุกหน้าต้องมี

| สถานะ | ทำอย่างไร |
|---|---|
| กำลังโหลด | skeleton ตามรูปร่างจริงของหน้า ไม่ใช้ spinner เต็มจอ ถ้าเกิน 10 วินาทีให้แสดงปุ่มลองใหม่ |
| ว่าง | ใช้ข้อความบอกว่าทำไมว่าง และปุ่มทำขั้นถัดไป เช่น Schedule / Empty, Grade Calculator · No Transcript |
| ผิดพลาดจาก server | ข้อความภาษาไทยพร้อมปุ่มลองใหม่ ห้ามแสดง error ดิบหรือ stack trace |
| ออฟไลน์ | หน้า Offline ถ้ายังไม่เคยโหลดหน้านั้น ถ้าเคยโหลดแล้วให้แสดงข้อมูลล่าสุดพร้อมแถบบอกว่าออฟไลน์ |
| เซสชันหมดอายุ | Session Expired: เก็บสิ่งที่ยังไม่บันทึกไว้บนเครื่องก่อน แล้วให้เข้าสู่ระบบใหม่ในหน้าต่างเดิม |
| ไม่พบ | Not Found ทั้ง route ที่ไม่มี และรหัสวิชาที่ไม่มีในหลักสูตร |

## 4. Flow และ edge cases ราย feature

### 4.1 เข้าสู่ระบบ **MVP**

```
/sign-in → Google popup → สำเร็จ → บัญชีใหม่? → /onboarding/program
                                   └ บัญชีเดิม → next หรือ /
                    └ ไม่สำเร็จ → Sign In · Error
```

| กรณี | การรับมือ |
|---|---|
| ปิดหน้าต่าง Google หรือป๊อปอัปถูกบล็อก | Sign In · Error บอกให้อนุญาตป๊อปอัป ปุ่มเดิมกดซ้ำได้ |
| เปิดใน in-app browser ของแอปอื่นที่ Google ไม่ให้เข้า | ตรวจ user agent แล้วแนะนำให้เปิดใน Safari หรือ Chrome พร้อมปุ่มคัดลอกลิงก์ |
| กดปุ่มซ้ำหลายครั้ง | ปิดปุ่มระหว่างรอ |
| เข้าด้วยบัญชีอื่นขณะมีข้อมูลค้างบนเครื่อง | ใช้ข้อมูลของบัญชีที่เพิ่งเข้าสู่ระบบ และลบข้อมูลที่ค้างบนเครื่องของบัญชีเดิม ไม่ถามและไม่รวมสองชุด |
| เซสชันหมดอายุแล้วเข้าด้วยบัญชีเดิม | ส่งสิ่งที่ค้างบนเครื่องขึ้นบันทึกต่อ |
| ออกจากระบบ | ล้างข้อมูลส่วนตัวที่ cache ไว้บนเครื่อง |

### 4.2 Onboarding และ transcript **MVP**

```
Choose Program → Transcript Upload → Reading → Review → (Needs Attention → แก้ครบ) → ยืนยัน → Home
                               ├→ Error → เลือกไฟล์ใหม่
                               └→ ข้ามไปกรอกเอง → Grade Calculator · No Transcript
```

ไฟล์อ่านบนเครื่องผู้ใช้ (ตามที่ออกแบบในหน้า Upload) และบันทึกเฉพาะรายการวิชาหลังกดยืนยัน

| กรณี | การรับมือ |
|---|---|
| ไม่ใช่ PDF, เกิน 5 MB | ตรวจก่อนอ่าน แสดง Transcript Upload · Error |
| PDF ล็อกรหัสผ่าน, เป็นรูปสแกน (ไม่มีข้อความ), ไม่ใช่ transcript KU | แสดง Error พร้อมเงื่อนไขไฟล์ที่อ่านได้ |
| อ่านนาน | Reading มีแถบความคืบหน้าและปุ่มยกเลิก |
| เกรดอ่านไม่ได้ | Needs Attention ไฮไลต์แถว ปุ่มยืนยันกดไม่ได้จนกว่าจะเลือกเกรด |
| ลงวิชาซ้ำ (retake) | ใช้เกรดครั้งล่าสุดคำนวณ GPAX และหน่วยกิต ครั้งก่อนแสดงเป็นประวัติแบบขีดฆ่า ไม่นับซ้ำ |
| เกรด P, S, U, W, I | ไม่นับใน GPAX P นับหน่วยกิตตามหมวด W/I ไม่นับ แสดงเครื่องหมาย `*` |
| วิชาที่ไม่อยู่ในหลักสูตรที่เลือก | นับเป็นวิชาเลือกเสรีก่อน ผู้ใช้ย้ายหมวดได้ |
| วิชาที่กำลังเรียน (ไม่มีเกรด) | ใช้เติมตารางเรียนและตัวคำนวณ ไม่นับใน GPAX |
| transcript เป็นของอีกสาขา | เตือนว่าไม่ตรงกับหลักสูตรที่เลือก ให้เลือกว่าจะเปลี่ยนหลักสูตรหรือใช้ต่อ |
| GPAX ที่คำนวณไม่ตรงกับในไฟล์ | แสดงทั้งสองค่าและวิชาที่น่าจะอ่านผิด |
| ข้อความในไฟล์มีชื่อ รหัสนิสิต เลขบัตรประชาชน | ไม่อ่าน ไม่เก็บ ไม่ส่งออกจากเครื่อง |
| อัปโหลดใหม่ภายหลังจาก Settings | แสดงความต่างจากข้อมูลเดิมก่อนแทนที่ คะแนนที่จำลองไว้ของวิชาเดิมยังอยู่ |

### 4.3 คำนวณเกรด **MVP**

| กรณี | การรับมือ |
|---|---|
| ไม่มีวิชาที่กำลังเรียน | Grade Calculator · No Transcript มีทางอัปโหลดหรือกรอก GPAX เอง |
| น้ำหนักรวมไม่ถึงหรือเกิน 100% | แสดงผลรวมตลอด ยังคำนวณได้แต่เตือนว่าผลอาจไม่ตรง |
| คะแนนเกินคะแนนเต็ม, ติดลบ, ไม่ใช่ตัวเลข | แจ้งใต้ช่องนั้นทันที ไม่นำไปคำนวณ |
| final ต้องได้เกิน 100% | แสดงว่าเกรดนั้นเป็นไปไม่ได้แล้ว ไม่แสดงตัวเลขเกินเต็ม |
| ได้เกรดนั้นแน่นอนแล้วแม้ final ได้ 0 | แสดงว่าได้แล้ว |
| เกณฑ์ตัดเกรดแต่ละวิชาไม่เหมือนกัน | ให้แก้เกณฑ์ได้ ค่าเริ่มต้นเป็นเกณฑ์ที่ใช้บ่อย และบอกว่าเป็นค่าประมาณ |
| วิชาแบบ S/U | คำนวณผ่านหรือไม่ผ่านอย่างเดียว ไม่มีผลต่อ GPAX |
| บันทึก | บันทึกอัตโนมัติหลังหยุดพิมพ์ 1 วินาที ไม่มีปุ่มบันทึก จึงไม่ต้องถามก่อนออกจากหน้า |
| บันทึกไม่สำเร็จ | Grade Calculator · Save Failed: เก็บบนเครื่อง ลองใหม่อัตโนมัติ และมีปุ่มลองตอนนี้ |
| เปิดหลายแท็บแล้วแก้พร้อมกัน | ใช้ค่าที่แก้ล่าสุด และแท็บอื่นโหลดค่าใหม่เมื่อกลับมาที่แท็บ |

### 4.4 ตารางเรียน การแชร์ และ wallpaper **MVP**

| กรณี | การรับมือ |
|---|---|
| ยังไม่มีวิชาหรือเวลาเรียน | Schedule / Empty |
| วิชาที่ลงไว้แต่ยังไม่ใส่เวลา | อยู่ในรายการด้านขวา ไม่อยู่บนตาราง และมีป้ายให้ใส่เวลา |

| กราฟบนจอแคบ | MVP ไม่รองรับมือถือ ดูหัวข้อ 5.2 |

### 4.6b หน้าวิชา `/course/[code]`

มีหน้าเดียวคือ Course Overview (รวม Course Detail เดิมเข้ามาแล้ว) แถวข้อมูลหลัก 4 ช่องเปลี่ยนตามสถานะของผู้ใช้กับวิชานั้น

| สถานะ | ช่อง "สถานะของคุณ" | ช่อง "ตารางเรียน" | ปุ่มหลัก |
|---|---|---|---|
| ผ่านแล้ว | เกรดที่ได้ และภาคที่เรียน | ซ่อน แสดงจำนวนวิชาที่ปลดล็อกแทน | ดูวิชาที่เรียนต่อได้ |
| กำลังเรียน | รอเกรด · ภาคปัจจุบัน | ใส่เวลาแล้ว หรือยังไม่ใส่เวลา | คำนวณเกรด |
| ลงได้ | ยังไม่ได้ลง · เงื่อนไขครบ | ยังไม่อยู่ในตาราง | เพิ่มในแผนเทอมหน้า |

### 4.7 ส่วนที่นิสิตช่วยกันเขียน (หลัง MVP)

ทุกหน้าในกลุ่มนี้ต้องมี:

- **สิทธิ์:** อ่านได้โดยไม่ต้องยืนยัน ส่วนการเขียนต้องยืนยันนิสิต KU ก่อน

- **รายการว่าง:** มีสถานะว่าง เช่น Reviews Empty

## 5. กติกาข้อมูลที่ frontend ต้องใช้ตรงกัน

- **ปีการศึกษา:** เก็บเป็นปี พ.ศ. กับภาค (`2569-1`, `2569-2`, `2569-S`) และแสดงเป็น "ภาคต้น 2569"
- **เวลา:** ใช้ `Asia/Bangkok` เสมอ เก็บเวลาเรียนเป็น `HH:mm` ไม่ผูกวันที่
- **ชื่อ:** แสดงชื่ออังกฤษก่อน ชื่อไทยเป็นบรรทัดรอง ส่วนรหัสวิชาเป็นข้อความ 8 หลัก ห้ามแปลงเป็นตัวเลขเพราะจะเสียเลข 0 ข้างหน้า
- **GPAX และ GPA:** คำนวณด้วยค่าเต็ม แล้วแสดงทศนิยม 2 ตำแหน่ง แบบตัดเศษ (3.578 → 3.57) ห้ามปัดค่าระหว่างคำนวณ ตอนทดสอบให้เทียบกับค่าใน transcript จริง ถ้าไม่ตรงให้เปลี่ยนเป็นปัดเศษที่ฟังก์ชันเดียว
- **ลงวิชาซ้ำ:** ใช้เกรดครั้งล่าสุดเท่านั้น
- **สี:** ทุกสีมาจาก token ใน Figma (`text/*`, `surface/*`, `status/*`, `feature/*`) และต้องผ่าน contrast 4.5:1 ทั้ง Light และ Dark
- **ฟอร์ม:** ป้ายอยู่เหนือช่องเสมอ ข้อผิดพลาดอยู่ใต้ช่องที่ผิด และปุ่มส่งปิดระหว่างรอ

### 5.1 รูปแบบข้อมูลเงื่อนไขวิชา

เก็บเงื่อนไขของแต่ละวิชาในแต่ละหลักสูตรเป็นต้นไม้ของ `all` และ `any` เพื่อให้เขียนได้ทั้ง "และ" "หรือ" และซ้อนกัน

```ts
type Requirement =
  | { type: "all"; items: Requirement[] }            // ต้องครบทุกข้อ
  | { type: "any"; items: Requirement[] }            // ข้อใดข้อหนึ่ง
  | { type: "course"; code: string; kind: "pass" | "taken" | "concurrent"; minGrade?: Grade }
  | { type: "credits"; min: number; category?: string } // เช่น ผ่านแล้ว 90 หน่วยกิต
  | { type: "year"; min: number }                     // เช่น นิสิตชั้นปีที่ 3 ขึ้นไป
  | { type: "consent" };                              // ได้รับอนุญาตจากภาควิชา

type CourseRule = {
  curriculumId: string;
  code: string;                 // รหัสวิชาเป็นข้อความ 8 หลัก
  requirement: Requirement | null; // null = ไม่พบข้อมูลเงื่อนไข
  source: string;               // ที่มาของข้อมูล ใช้ตรวจความถูกต้อง
};
```

- **`pass`:** ต้องผ่านก่อน ใช้เกรดครั้งล่าสุด และผ่านเมื่อไม่ใช่ F, U หรือ W
- **`taken`:** เคยลงเรียนแล้ว ไม่ผ่านก็ลงได้ ครบเมื่อมีเกรดใดก็ได้รวม F ในครั้งใดก็ได้ แต่ไม่นับ W และถ้ากำลังเรียนวิชานั้นอยู่ให้เป็น `pending`
- **`concurrent`:** เรียนก่อนหรือพร้อมกัน ครบเมื่อผ่านแล้ว กำลังเรียน หรืออยู่ในแผนเทอมเดียวกัน
- **`null` กับ `{ type: "all", items: [] }`:** ต่างกัน ค่าแรกคือไม่มีข้อมูลเงื่อนไข (กรอบเทาประ) ส่วนค่าที่สองคือไม่มีเงื่อนไขจริง ลงได้เลย

**การหาสถานะ:** ตรวจแต่ละข้อแล้วได้หนึ่งในสามค่า ได้แก่ `met` (ครบ), `pending` (ครบถ้าวิชาที่กำลังเรียนผ่าน) และ `unmet` (ยังขาด) ค่า `all` ใช้ค่าที่แย่ที่สุดของลูก ส่วน `any` ใช้ค่าที่ดีที่สุด แล้วแปลงเป็นสถานะการ์ดดังนี้

| ค่า | สถานะการ์ด |
|---|---|
| `met` | ลงได้ |
| `pending` | ต้องผ่าน… (กรอบเหลืองจุด) |
| `unmet` | ยังลงไม่ได้ |
| เงื่อนไขเป็น `null` | ไม่พบเงื่อนไข |

**การวาดกราฟ:**

| รูปแบบ | วิธีวาด |
|---|---|
| `pass` | เส้นทึบมีลูกศรเหมือนตอนนี้ |
| `taken` | เส้นจุด มีป้าย "ไม่ผ่านก็ลงได้" |
| `concurrent` | เส้นประ มีป้าย "เรียนพร้อมกันได้" |
| `any` | เส้นจากทุกวิชาเข้าจุดกลมเล็กที่เขียนว่า "หรือ" แล้วมีเส้นเดียวต่อเข้าวิชาปลายทาง |
| `credits`, `year`, `consent` | ไม่วาดเป็นเส้น แสดงเป็นป้ายบนการ์ดและรายการเงื่อนไขใน overlay |

**การเก็บใน Supabase:** เก็บ `requirement` เป็น `jsonb` ในตาราง `course_rules` และสร้างตาราง `course_edges(from_code, to_code, kind, group_id)` จากต้นไม้นี้ด้วยสคริปต์ เพื่อให้วาดกราฟและหาเส้นทางได้ง่าย ฝั่ง frontend ไม่ต้องแปลงต้นไม้เอง

### 5.2 ขนาดหน้าจอใน MVP

- **ขนาดที่รองรับ:** desktop ตั้งแต่กว้าง 1024px ขึ้นไป ถ้าจอแคบกว่านั้นให้แสดงแถบแจ้งว่ายังไม่รองรับมือถือ แต่ไม่บล็อกการใช้งาน
- **ข้อยกเว้น 1 (`/s/[token]`):** เพื่อนจะเปิดลิงก์แชร์บนมือถือเป็นส่วนใหญ่ หน้านี้จึงต้องอ่านได้ที่กว้าง 375px โดยเรียงวันเป็นรายการแนวตั้งแทนตาราง (เฟรม `Mobile / Shared Schedule · Viewer` และ `· Link Unavailable` ใน section `4b` แต่ละวันแสดงเวลา รหัสวิชา และชื่อวิชา)
- **ข้อยกเว้น 2 (รูป wallpaper):** เลือกขนาดรูปได้ 3 แบบ ไม่ว่าจะสร้างจากเครื่องไหน ได้แก่ มือถือ 1170×2532 (เฟรม `Wallpaper / Phone` วาดที่ 390×844 export @3x), แท็บเล็ต 2048×2732 (`Wallpaper / Tablet` 1024×1366 @2x) และคอมพิวเตอร์ 2560×1440 (`Wallpaper / Desktop` 1280×720 @2x) ค่าเริ่มต้นคือมือถือ
